# Исправление импорта в последней версии Sprint 21

За основу взят присланный архив `GtStore-v6.20-SPRINT-21-CUSTOMER-ACCOUNTS.zip`.
Сохранены его интерфейс, три уровня каталога, вариации, настройки импорта, API ключи,
ACL, доставка, платежи, Telegram/Mini App, поддержка и остальные модули.
Рабочая база, фотографии, `node_modules` и настройки редакторов из архива не публиковались.

## Причина остановки на 0%

Интерфейс ждал окончания POST первых 100 товаров. Их фотографии скачивались
последовательно, с таймаутом 45 секунд на каждую. Один и тот же URL запрашивался
повторно для разных товаров. Первый ответ мог задерживаться на десятки минут,
а прогресс до этого оставался на нуле.

## Исправление

- Запуск фонового задания возвращает HTTP 202; браузер отдельно получает прогресс.
- Фото скачиваются с ограничением параллельности, времени и размера, проверкой TLS,
  публичного адреса и содержимого. Общие источники используют дисковый кеш.
- Каталог сохраняется пакетами по 25 товаров. Ошибки показывают SKU и причину.
- Страница после обновления подключается к тому же заданию. Статусы и фотографии
  сохраняются на диске; прерванное перезапуском API задание явно помечается как прерванное.
- Повторный импорт сохраняет ID товаров/вариаций и не стирает ручные фотографии
  из-за пустых фото-колонок. Удаление отсутствующих позиций выполняется только
  после полного успешного импорта. По умолчанию удаление выключено.
- Сохранены генерация WebP-миниатюр и работа изображений через HTTPS/адрес API.

## Что проверено

Оба Excel-файла `gstore13v4.xlsx` и `gstore13v4-with-display.xlsx` импортируются
фоновым заданием: по 1 219 товаров и 97 уникальных источников фотографий.
Проверены кеш после перезапуска, повторная загрузка, ошибки, пропуск строк,
защита от удаления используемых фото и от небезопасных URL.

В Chromium выполнены вход в админку, загрузка Excel, прогресс до первого сохранения,
обновление страницы во время скачивания, завершение импорта и отображение всех
1 219 изображений. Сетевой транспорт источников фото имитировался: это проверяет
сохранение, соответствие URL и отображение, но не доступность настоящих ссылок i.ibb.co.

## Установка

Код находится в GitHub. Для управляемых обновлений используйте
[GitHub → Timeweb](GITHUB_DEPLOY.md). Перед первой активацией нужно подтвердить
расположение и способ запуска существующего сайта, сохранить базу, фото и секреты.

Архив исправленного кода не содержит production-базы, загрузок, секретов и зависимостей.
При обновлении существующей установки сохраняйте её `data/`, `uploads/` и `.env`;
не используйте удаление всех отсутствующих в новом архиве файлов. После установки
зависимостей из lockfile и перезапуска API обновите открытую вкладку админки.

Изменённый код сам по себе не означает, что VPS уже обновлён. Проверяйте реальную
версию `/api/v6/health` и полный импорт на работающем сервере отдельно.
