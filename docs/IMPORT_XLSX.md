# Импорт Excel и хранение фотографий

Импорт v6 принимает XLSX/XLS и CSV. Для двухлистного Excel используются листы
«Товары» и «Категории». Названия столбцов допускают пробелы, SKU может быть числом.
Цена и остаток проверяются до записи. Поддерживаются цены вида `1 234,50`.

Перед подтверждением показаны ошибки, количество строк и уникальных фотографий.
При повторном импорте товар с тем же SKU обновляется с сохранением ID; новые SKU
создаются. Пустое поле фотографии не стирает имеющуюся галерею. Файл задаёт цены,
остатки и вариации импортируемых товаров; проверьте предпросмотр перед подтверждением.

Ссылки на фото скачиваются сервером при подтверждении, а не при предпросмотре.
Одинаковый URL скачивается один раз. В карточках сохраняются серверные адреса
`/api/v6/media/import-<sha256>.<ext>`. Фото и индекс источников сохраняются на диске:
после перезапуска приложения они доступны без обращения к исходному фотохостингу.
Фотографию, которая ещё используется товаром, удалить через API нельзя.

Поддерживаются публичные HTTPS-ссылки на JPEG, PNG, GIF и WebP до 8 МБ. Проверяются
TLS, адрес назначения, перенаправления и тип содержимого. Недоступное или неподходящее
фото останавливает импорт до записи каталога; ошибка указывает SKU и адрес источника.
Уже скачанные фото остаются в кеше и используются при повторной попытке.
При использовании HTTPS-прокси он также должен блокировать внутренние адреса:
DNS-проверка приложения не заменяет контроль назначения на стороне прокси.

Каталог записывается одной транзакцией вместо перезаписи всей базы для каждого товара.
Пропуск некорректных строк включается явно; отчёт содержит количество и причины пропусков.

## Хранение на сервере

`V6_MEDIA_DIRECTORY` задаёт каталог фото; без неё используется `uploads/v6` относительно
рабочего каталога процесса. `V6_DATABASE_FILE` задаёт файл базы; по умолчанию `data/v6.json`.
Для VPS используйте постоянные абсолютные пути вне каталога сменяемого релиза.
Для контейнера оба пути должны находиться в постоянном томе.

Не меняйте путь существующей базы на пустой каталог. Перед сменой пути медиа
сохраните и перенесите существующие файлы вместе с подкаталогом `.import-cache`;
перед обновлением сделайте резервную копию текущей базы и фото. Выдайте процессу
приложения права чтения и записи этих каталогов. Не удаляйте их при обновлении кода.
В резервную копию включайте и базу, и медиа.

Внешнему серверу нужен исходящий HTTPS-доступ к источникам фотографий. В двух
проверенных файлах gstore13v4 это `i.ibb.co`: 1 219 строк и 97 уникальных URL.
Проксирование `/api/v6/media/` должно вести на API, `/admin/` — на админку,
а `/` — на витрину. Для длительной загрузки всех фото проверьте таймауты обратного
прокси; например, `proxy_read_timeout 300s` для маршрутов импорта Nginx.

## Как определить способ развёртывания Timeweb

В репозитории подготовлены GitHub Actions, скрипты развёртывания и примеры systemd/Nginx:
см. [GitHub → Timeweb](GITHUB_DEPLOY.md). Они требуют однократной подготовки VPS.
Расположение уже установленного приложения нельзя определить по одному IP или
паролю админки.

В панели Timeweb проверьте, находится ли ресурс в «Облачных серверах» (VPS)
или в «Приложениях» с подключённым GitHub. Для VPS откройте консоль сервера.
Следующие команды только показывают работающие Node-процессы, рабочие каталоги
и имена связанных сервисов, без вывода переменных среды или секретов:

```bash
ps -C node,nodejs -o pid=,user=,comm=
for pid in $(ps -C node,nodejs -o pid=); do
  printf 'PID %s: ' "$pid"
  readlink "/proc/$pid/cwd"
done
systemctl list-units --type=service --all --no-pager | grep -Ei 'gtstore|gstore|node|pm2|nginx' || true
```

Если используется Docker, `docker ps --format '{{.Names}} {{.Image}} {{.Ports}}'`
покажет имена контейнеров. Не публикуйте `docker inspect`, `.env`, переменные
процессов, ключи или пароли: для определения способа обновления они не нужны.
После определения каталога проекта и процесса можно подготовить точные команды
обновления, резервного копирования и перезапуска без догадок об устройстве сервера.

## Проверки

```bash
npm run v6:test
npm run typecheck
npm run verify
# Дополнительно проверить конкретные файлы, не добавляя их в репозиторий:
node tests/v6/import-persistence.test.mjs /path/to/gstore13v4.xlsx /path/to/gstore13v4-with-display.xlsx
```

Тест импорта проверяет 1 219 товаров, сопоставление 97 фото, повторный импорт,
выдачу фото после перезапуска и недоступности фотохостинга. Его сетевой транспорт
имитируется: успешный тест не подтверждает доступность внешних ссылок или установку
исправления на Timeweb. Проверка настоящих фото и развёрнутого приложения выполняется
отдельно после получения сетевого доступа и доступа к управлению сервером.
